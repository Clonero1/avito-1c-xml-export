# avito-1c-xml-export

Техническая база для разработки внешней обработки 1С ERP 2.5, которая формирует XML-файл автозагрузки Авито по остаткам, ценам и фотографиям из 1С.

## Назначение

Проект описывает обработку для 1С ERP 2.5.25.101 на платформе 1С:Предприятие 8.3.27.1688.

Обработка должна:

- читать текущий рабочий XML Авито как шаблон;
- сопоставлять объявления XML с номенклатурой 1С;
- оставлять в выгрузке товары с положительным остатком;
- исключать из нового XML товары без остатка;
- обновлять цену по типу цен `Кинезис`;
- получать фотографии из присоединённых файлов номенклатуры;
- выгружать фотографии на внешний сервер или сайт;
- подставлять публичные URL фотографий в XML;
- формировать отчёты ошибок, новых товаров, снятых товаров, товаров без фото и дублей.

## Текущий статус

В репозитории пока нет готовой `.epf` обработки. На текущем этапе подготовлена техническая база и заготовки модулей для 1С-разработчика.

## Текущий этап разработки

- Готова только техническая база проекта.
- Готовой `.epf` обработки пока нет.
- Текущая цель следующего этапа — прототип чтения текущего XML, сопоставления объявлений с остатками 1С и формирования нового XML.
- Фото на этом этапе не реализуются.
- Новые товары на этом этапе не добавляются автоматически, а только попадают в отчёт новых товаров.
- Первый прототип должен использовать текущий XML Авито как шаблон и менять только цену, если новая цена найдена.

## Ключевая архитектурная логика

На первом этапе нельзя генерировать весь XML с нуля. Нужно использовать текущий рабочий XML как шаблон, потому что в нём уже есть корректные поля Авито: категории, типы запчастей, описания, фотографии и старые ID объявлений.

Основной сценарий:

1. Прочитать текущий XML.
2. Сопоставить объявления XML с номенклатурой 1С.
3. Если товар есть в 1С и остаток больше нуля, оставить объявление в новом XML.
4. Если товар есть в XML, но отсутствует в остатках, исключить из нового XML и записать в отчёт снятых.
5. Если товар есть в 1С, но отсутствует в XML, записать его в отчёт новых товаров.
6. Обновить цену из типа цен `Кинезис`.
7. Обновить фотографии, если они есть.

## Ключ связи 1С и Авито

Лучший вариант — дополнительный реквизит номенклатуры `Avito_ID`.

Если `Avito_ID` заполнен, он используется как основной ключ связи.

Если `Avito_ID` не заполнен, используется резервное сопоставление по нормализованному OEM, артикулу и дополнительным каталожным номерам.

## Фото

Фотографии хранятся в карточке номенклатуры в присоединённых файлах. Авито принимает только публичные URL фотографий:

```xml
<Images>
  <Image url="https://site.ru/avito/images/RS-00180081_1.jpg"/>
</Images>
```

Способ выгрузки фото на сервер пока не выбран и вынесен в [open_questions.md](./open_questions.md).

## Python-прототип сопоставления

Проверяемый Python-прототип лежит в [prototype/](./prototype/). Он нужен, чтобы до переноса логики в 1С отладить сопоставление текущего XML Авито и Excel-выгрузки остатков из 1С.

Команды из корня репозитория:

```bash
python -m pip install -r prototype/requirements.txt
python -m pytest prototype/tests
python prototype/compare_avito_xml_with_1c_stock.py --config prototype/sample_config.json
```

Прототип проверяет нормализацию артикулов/OEM, поиск совпадений, снятие объявлений без остатка, список новых товаров и дубли OEM в XML на реальных XML/XLSX перед переносом логики в 1С. Он не является обработкой 1С, не создаёт `.epf`, не выгружает фото и не добавляет новые товары в XML автоматически.
