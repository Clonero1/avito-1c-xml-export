# Техническое задание

## Внешняя обработка 1С ERP для формирования XML-файла автозагрузки Авито с фотографиями

### 1. Цель разработки

Разработать внешнюю обработку 1С ERP для автоматического формирования XML-файла автозагрузки объявлений на Авито по товарам, имеющим положительный остаток на выбранных складах.

Обработка должна:

* получать остатки товаров из 1С ERP;
* получать цены по типу цен «Кинезис»;
* получать фотографии из присоединённых файлов номенклатуры;
* выгружать фотографии на внешний сервер/сайт;
* формировать публичные ссылки на фотографии;
* формировать XML-файл в формате Авито XML;
* исключать из выгрузки товары без остатка;
* обновлять существующие объявления;
* формировать отчёт ошибок и товаров, требующих ручной проверки.

---

### 2. Формат реализации

Рекомендуемый формат реализации на первом этапе:

**внешняя обработка 1С `.epf`**

Причины выбора внешней обработки:

* не требует изменения типовой конфигурации ERP;
* безопасна для тестирования;
* проще дорабатывать;
* можно запускать вручную;
* в дальнейшем можно перенести функционал в расширение или регламентное задание.

---

### 3. Конфигурация 1С

Используемая система:

* **1С ERP**
* конфигурация: **ERP 2.5**
* платформа: уточнить у заказчика / администратора 1С.

---

### 4. Источник товаров

Товары для выгрузки должны отбираться по положительному остатку на следующих складах:

1. **Агрегаты восстановленные Реман (Суставов А.)**
2. **Склад Исток Основной**
3. **Склад форсунки восстановленные Исток (Суставов А.)**
4. **Склад деталей REMAN (Суставов А.)**
5. **Склад форсунки восстановленные Кимры**
6. **Склад РВД Исток**

В XML должны попадать только товары, у которых суммарный доступный остаток по указанным складам больше нуля.

---

### 5. Источник цены

Цена товара должна браться из 1С по типу цен:

**Кинезис**

Если цена по типу цен «Кинезис» не найдена, товар не должен попадать в основной XML. Такой товар должен попадать в отдельный отчёт ошибок с причиной:

> Не заполнена цена по типу цен «Кинезис».

---

### 6. Источник фотографий

Фотографии товара хранятся в 1С:

**в карточке номенклатуры в присоединённых файлах.**

Обработка должна:

1. Найти присоединённые файлы номенклатуры.
2. Отобрать файлы изображений:

   * `.jpg`
   * `.jpeg`
   * `.png`
   * `.webp`, если поддерживается сервером и Авито.
3. Выгрузить изображения на внешний сервер/сайт.
4. Получить публичные URL-ссылки.
5. Подставить ссылки в XML в блок:

```xml
<Images>
  <Image url="https://site.ru/avito/images/RS-00180081_1.jpg"/>
  <Image url="https://site.ru/avito/images/RS-00180081_2.jpg"/>
</Images>
```

Важно: Авито не принимает фотографии как вложения внутри XML. Авито принимает только URL-ссылки на изображения.

---

### 7. Требования к хранению фотографий на сервере

Необходимо предусмотреть отдельную папку на сайте или сервере, например:

```text
/avito/images/
```

Пример итоговой ссылки:

```text
https://kinesisgt.ru/avito/images/RS-00180081_1.jpg
```

Требования к ссылкам:

* ссылка должна открываться без авторизации;
* ссылка должна быть прямой;
* сервер должен отдавать именно изображение, а не страницу предпросмотра;
* ссылка должна начинаться с `https://`;
* изображение должно быть доступно Авито извне.

Рекомендуемое именование файлов:

```text
КодНоменклатуры_НомерФото.jpg
```

Пример:

```text
RS-00180081_1.jpg
RS-00180081_2.jpg
RS-00180081_3.jpg
```

### 8. Связь товара 1С с объявлением Авито

Наиболее надёжный вариант — добавить в 1С дополнительный реквизит номенклатуры:

```text
Avito_ID
```

В этом реквизите должен храниться ID объявления Авито из XML:

```text
reman8900461
```

Если `Avito_ID` заполнен, обработка должна использовать его как основной ключ связи.

Если `Avito_ID` не заполнен, допускается резервное сравнение по нормализованному артикулу/OEM.

Нормализация артикула должна учитывать:

* удаление дефисов;
* удаление пробелов;
* приведение к верхнему регистру;
* сравнение артикулов вида `270-5323` и `2705323`;
* сравнение артикулов с суффиксами, например `3918776RN` и `3918776`, если это согласовано с заказчиком;
* обработку нескольких артикулов через `/`, `,`, `;`.

### 9. Рекомендуемые дополнительные реквизиты номенклатуры

Для стабильной работы выгрузки рекомендуется добавить в номенклатуру следующие дополнительные реквизиты:

| Реквизит                     | Назначение                     |
| ---------------------------- | ------------------------------ |
| `Avito_ID`                   | постоянный ID объявления Авито |
| `Avito_Category`             | категория Авито                |
| `Avito_GoodsType`            | вид товара                     |
| `Avito_ProductType`          | тип товара                     |
| `Avito_SparePartType`        | вид запчасти                   |
| `Avito_TechnicSparePartType` | тип запчасти                   |
| `Avito_FuelSystemPartType`   | тип запчасти топливной системы |
| `Avito_HydraulicDesignType`  | тип гидравлики                 |
| `Avito_Title`                | заголовок объявления           |
| `Avito_Description`          | описание объявления            |
| `Avito_ManagerName`          | контактное лицо                |
| `Avito_ContactPhone`         | телефон                        |
| `Avito_Address`              | адрес объявления               |
| `Avito_Condition`            | состояние товара               |
| `Avito_Originality`          | происхождение: оригинал/аналог |
| `Avito_Brand`                | производитель для Авито        |

Если часть этих реквизитов не заполнена, обработка должна использовать значения по умолчанию или выводить товар в отчёт ошибок.

### 10. Логика состояния товара

Состояние товара должно определяться по складу или по отдельному реквизиту.

Предварительная логика:

| Склад                                              | Состояние для Авито   |
| -------------------------------------------------- | --------------------- |
| Склад Исток Основной                               | Новое                 |
| Склад РВД Исток                                    | Новое                 |
| Склад деталей REMAN (Суставов А.)                  | Б/у                   |
| Агрегаты восстановленные Реман (Суставов А.)       | Б/у / восстановленное |
| Склад форсунки восстановленные Исток (Суставов А.) | Б/у / восстановленное |
| Склад форсунки восстановленные Кимры               | Б/у / восстановленное |

Для Авито использовать допустимые значения поля:

```xml
<Condition>Новое</Condition>
```

или

```xml
<Condition>Б/у</Condition>
```

Если один и тот же артикул находится на разных складах с разным состоянием, обработка должна выводить такую позицию в отчёт ручной проверки, чтобы не объединять новый и б/у товар в одно объявление.

### 11. Основной сценарий работы обработки

Обработка должна иметь форму с настройками:

* выбор складов;
* выбор типа цен;
* путь сохранения XML;
* путь/адрес для выгрузки фотографий;
* базовый URL фотографий;
* режим работы:

  * сформировать XML;
  * только проверить данные;
  * сформировать отчёты без XML.

Алгоритм:

1. Пользователь открывает обработку.
2. Проверяет настройки.
3. Нажимает кнопку **«Сформировать XML Авито»**.
4. Обработка получает остатки по выбранным складам.
5. Обработка получает цены по типу цен «Кинезис».
6. Обработка получает данные номенклатуры.
7. Обработка получает присоединённые файлы-фотографии.
8. Обработка выгружает фотографии на сервер.
9. Обработка формирует XML.
10. Обработка формирует отчёты.
11. Пользователь получает:

    * XML-файл;
    * отчёт ошибок;
    * отчёт товаров без фото;
    * отчёт новых товаров;
    * отчёт снятых товаров.

### 12. Логика формирования XML

Корневой элемент XML:

```xml
<Ads target="Avito.ru" formatVersion="3">
```

Каждый товар должен формироваться как отдельный блок:

```xml
<Ad>
  <Id>reman8900461</Id>
  <ListingFee>Package</ListingFee>
  <ManagerName>Юрий</ManagerName>
  <ContactPhone>79161100630</ContactPhone>
  <Address>Московская область, Сергиев Посад город, улица Фабричная, д 4а/5а</Address>
  <ContactMethod>По телефону и в сообщениях</ContactMethod>
  <Category>Запчасти и аксессуары</Category>
  <Description>Описание товара</Description>
  <Title>Название объявления</Title>
  <Price>10000</Price>
  <PriceWithVAT>Да</PriceWithVAT>
  <PostponedPayment>Нет</PostponedPayment>
  <GoodsType>Запчасти</GoodsType>
  <AdType>Товар приобретен на продажу</AdType>
  <ProductType>Для спецтехники</ProductType>
  <SparePartType>Двигатели и комплектующие</SparePartType>
  <TechnicSparePartType>Система охлаждения</TechnicSparePartType>
  <Condition>Б/у</Condition>
  <Availability>В наличии</Availability>
  <Originality>Оригинал</Originality>
  <Brand>Caterpillar</Brand>
  <OEM>2705323</OEM>
  <TargetAudience>Частные лица и бизнес</TargetAudience>
  <Images>
    <Image url="https://site.ru/avito/images/RS-00180081_1.jpg"/>
  </Images>
</Ad>
```

### 13. Работа с текущим XML как с шаблоном

На первом этапе рекомендуется не формировать все поля Авито с нуля, а использовать текущий рабочий XML как шаблон.

Обработка должна:

1. Читать текущий XML.
2. Для каждого объявления искать соответствующую номенклатуру в 1С.
3. Если товар найден и остаток > 0:

   * оставить объявление;
   * обновить цену;
   * обновить фотографии;
   * при необходимости обновить описание.
4. Если товар не найден или остаток = 0:

   * не включать объявление в новый XML;
   * записать в отчёт «Снято с выгрузки».
5. Если товар есть в 1С, но отсутствует в XML:

   * не добавлять автоматически, если не заполнены обязательные поля Авито;
   * вывести в отчёт «Новые товары для добавления».

Такой подход снижает риск ошибок, потому что в текущем XML уже есть корректные поля Авито.

---

### 14. Проверки перед выгрузкой

Обработка должна проверять:

| Проверка                                           | Действие                                                 |
| -------------------------------------------------- | -------------------------------------------------------- |
| Нет цены                                           | не выгружать, записать в ошибки                          |
| Нет артикула/OEM                                   | не выгружать или отправить на ручную проверку            |
| Нет остатка                                        | не выгружать                                             |
| Нет фото                                           | выгружать, но записать в предупреждения                  |
| Нет `Avito_ID`                                     | использовать резервное сравнение по OEM                  |
| Не заполнен тип запчасти                           | не выгружать новые товары, записать в ошибки             |
| Один артикул на разных складах с разным состоянием | отправить на ручную проверку                             |
| Несколько объявлений с одним OEM                   | отправить в отчёт дублей                                 |
| Невозможно выгрузить фото на сервер                | выгрузить без фото или записать в ошибки, режим уточнить |

### 15. Отчёты обработки

Обработка должна формировать следующие отчёты:

#### 15.1. Отчёт выгруженных товаров

Поля:

* `Avito_ID`
* код 1С
* артикул/OEM
* наименование
* цена
* остаток
* склад
* количество фото
* статус выгрузки

#### 15.2. Отчёт ошибок

Поля:

* код 1С
* артикул/OEM
* наименование
* причина ошибки

Возможные причины:

* нет цены;
* нет остатка;
* нет артикула;
* не заполнена категория Авито;
* не заполнен тип запчасти;
* не удалось выгрузить фото;
* не найдено соответствие с XML;
* конфликт состояния товара по складам.

#### 15.3. Отчёт товаров без фото

Поля:

* код 1С
* артикул/OEM
* наименование
* остаток
* склад
* цена

#### 15.4. Отчёт новых товаров

Поля:

* код 1С
* артикул/OEM
* наименование
* цена
* остаток
* склад
* производитель
* какие поля Авито нужно заполнить

#### 15.5. Отчёт снятых товаров

Поля:

* `Avito_ID`
* OEM
* название объявления
* причина снятия:

  * нет остатка;
  * не найден в 1С;
  * нет цены;
  * отключён для выгрузки.

#### 15.6. Отчёт дублей

Поля:

* OEM
* количество объявлений в XML;
* список `Avito_ID`;
* список названий;
* рекомендация: проверить вручную.

Для работы фото необходим сервер или сайт с доступом по HTTPS.

### 20. Логика ежедневного использования

После настройки обработка должна использоваться по следующему сценарию:

1. Менеджер или ответственный сотрудник запускает обработку утром.
2. Обработка формирует новый XML.
3. XML загружается на сервер или передаётся в Авито.
4. Авито забирает файл по ссылке.
5. Ответственный проверяет отчёт ошибок.
6. Новые товары с незаполненными полями дорабатываются отдельно.

На следующем этапе возможно настроить регламентное задание для автоматического формирования XML по расписанию.

### 21. Что не входит в первый этап

На первом этапе не требуется:

* автоматическая публикация через API Авито;
* автоматическая модерация объявлений;
* автоматическое заполнение всех категорий Авито с нуля;
* автоматическая SEO-генерация длинных описаний;
* интеграция с Битрикс24;
* интеграция с сайтом как полноценной PIM-системой.

Эти задачи можно вынести во второй этап.

### 22. Этапы внедрения

#### Этап 1. Прототип

* внешняя обработка `.epf`;
* выбор складов;
* получение остатков;
* получение цены «Кинезис»;
* чтение текущего XML;
* обновление цены и остатка;
* исключение товаров без остатка;
* формирование XML;
* формирование отчёта ошибок.

#### Этап 2. Фото

* получение присоединённых файлов;
* выгрузка фото на сервер;
* формирование URL;
* добавление блока `Images` в XML;
* отчёт товаров без фото.

#### Этап 3. Новые товары

* поиск товаров, которые есть в 1С, но отсутствуют в XML;
* отчёт новых товаров;
* заполнение обязательных полей Авито;
* добавление новых товаров в XML.

#### Этап 4. Автоматизация

* регламентное задание;
* автоматическое сохранение XML на сервер;
* автоматическое обновление ссылки для Авито;
* контроль ошибок.

### 24. Критерии готовности

Обработка считается готовой, если:

* формирует XML в формате Авито;
* XML проходит проверку Авито без критических ошибок;
* товары без остатка не попадают в XML;
* цена берётся по типу цен «Кинезис»;
* фото выгружаются на сервер и попадают в XML как публичные URL;
* формируются отчёты ошибок;
* новые товары без обязательных полей Авито не добавляются молча, а попадают в отдельный отчёт;
* результат можно использовать для ежедневной выгрузки.
