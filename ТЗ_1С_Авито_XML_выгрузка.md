# ТЗ: обработка 1С для формирования XML Авито

## Цель

Сделать внешнюю обработку 1С для ERP 2.5, которая формирует XML-файл автозагрузки Авито по товарам из 1С с учетом цен, остатков и фотографий.

## Среда

- Платформа: 1С:Предприятие 8.3.27.1688
- Конфигурация: 1C:ERP Управление предприятием 2.5.25.101
- Тип обработки на первом этапе: внешняя обработка `.epf`
- Рекомендуемый второй этап: расширение конфигурации, если нужна кнопка в интерфейсе ERP или регламентная выгрузка по расписанию

## Источники данных

Цена:

- тип цен: `Кинезис`

Остатки:

- `Агрегаты восстановленные Реман (Суставов А.)`
- `Склад Исток Основной`
- `Склад форсунки восстановленные Исток (Суставов А.)`
- `Склад деталей REMAN (Суставов А.)`
- `Склад форсунки восстановленные Кимры`
- `Склад РВД Исток`

Фото:

- из карточки номенклатуры;
- источник: присоединенные файлы;
- в XML Авито должны попадать не сами файлы, а публичные URL фотографий.

## Рекомендуемый сценарий работы

1. Пользователь открывает обработку.
2. Выбирает путь к текущему XML Авито, если нужно обновить существующие объявления.
3. Выбирает папку для сохранения нового XML.
4. Обработка получает из 1С номенклатуру с остатками по указанным складам.
5. Для каждого товара получает цену по типу цен `Кинезис`.
6. Получает присоединенные файлы-фотографии.
7. Формирует новый XML `Ads formatVersion="3" target="Avito.ru"`.
8. Создает отчет по проблемам:
   - нет цены;
   - нет остатка;
   - нет фото;
   - не найдено соответствие с объявлением;
   - не заполнены обязательные поля Авито.

## Важный момент по фотографиям

Авито не принимает картинки, встроенные внутрь XML. В XML должны быть ссылки:

```xml
<Images>
  <Image url="https://site.ru/avito/photo1.jpg"/>
</Images>
```

Поэтому обработке нужен один из вариантов:

1. В карточке товара уже есть публичные ссылки на фото.
2. Обработка выгружает фото из присоединенных файлов в папку на сайте/сервере, а в XML пишет URL.
3. Фото сначала вручную или автоматически загружаются на хостинг, после чего 1С хранит эти ссылки.

Без публичного хранилища фото можно сформировать XML без картинок, но полноценный XML с фото для Авито сформировать нельзя.

## Лучший вариант реализации

На первом этапе лучше делать не полностью новую выгрузку с нуля, а обработку по шаблону:

- вход: текущий рабочий XML Авито;
- обработка сохраняет все авитовские поля из существующих объявлений;
- из 1С обновляет цену, наличие, название, описание и фото;
- товары без остатка можно исключать из XML;
- новые товары попадают в отдельный отчет `Нужно заполнить поля Авито`.

Так безопаснее, потому что в текущем XML используются разные поля Авито: `SparePartType`, `TechnicSparePartType`, `FuelSystemPartType`, `HydraulicDesignType`, `Brand`, `OEM`, `Make`, `Model`, `Technic`, `Originality`, `Availability` и другие.

## Что нужно уточнить перед разработкой

1. Где в 1С хранится описание для Авито.
2. Где хранится OEM/артикул, который должен попадать в XML.
3. Какие товары выгружать:
   - все с остатком;
   - только из определенной группы номенклатуры;
   - только с признаком `Выгружать на Авито`.
4. Куда выгружать фото, чтобы Авито мог их скачать по ссылке.

## Правило связи товара 1С и объявления Авито

Товар 1С связывается с объявлением Авито по полю `Код` номенклатуры.

Пример кода:

```text
RS-00177963
```

Для надежной работы обработки этот код должен попадать в XML в одно из стабильных полей. Предпочтительный вариант:

```xml
<Id>RS-00177963</Id>
```

Если в текущем рабочем XML поле `Id` уже занято внутренними идентификаторами вида `reman...`, тогда нужно использовать один из вариантов:

- хранить код 1С в отдельном поле XML, например `OEM` или другом согласованном поле, если это не ломает правила Авито;
- вести отдельный регистр/таблицу соответствий в 1С: `КодНоменклатуры` -> `IdАвито`;
- один раз подготовить таблицу соответствий из старого XML и 1С.

Самый чистый вариант для будущей автоматической выгрузки: сделать `Код` номенклатуры основой для поля `Id`, потому что Авито использует `Id` как внешний стабильный идентификатор объявления.

## Итог

Создать такую обработку можно. Практичный путь:

1. Сначала сделать внешнюю обработку `.epf` для ручной выгрузки и проверки.
2. После проверки перенести логику в расширение ERP, если нужна кнопка в 1С или автоматическая выгрузка по расписанию.
