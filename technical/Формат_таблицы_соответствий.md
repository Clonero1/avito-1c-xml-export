# Формат таблицы соответствий 1С и XML

## Назначение

Таблица соответствий нужна, чтобы связать номенклатуру 1С со старыми объявлениями Авито и не создавать дубли.

Старые объявления уже имеют стабильные ID в XML, например:

```xml
<Id>reman8900461</Id>
```

Новые товары в 1С имеют код вида:

```text
RS-00180081
```

Без таблицы соответствий обработка не сможет надёжно понять, какое старое объявление соответствует какой номенклатуре.

## Поля таблицы

| Поле | Описание |
|---|---|
| `КодНоменклатуры` | Код номенклатуры 1С, например `RS-00180081` |
| `СсылкаНоменклатуры` | Ссылка на элемент справочника номенклатуры |
| `Артикул` | Артикул из 1С |
| `OEM` | OEM или каталожный номер |
| `IdXML` | Значение поля `Id` из XML |
| `AvitoId` | Значение поля `AvitoId`, если есть |
| `НазваниеXML` | Заголовок объявления из XML |
| `ДатаСопоставления` | Дата создания или обновления связи |
| `ИсточникСопоставления` | `manual`, `Avito_ID`, `OEM`, `Артикул`, `ДопКаталожныйНомер` |
| `Комментарий` | Комментарий по спорным случаям |

## Пример

```csv
КодНоменклатуры,СсылкаНоменклатуры,Артикул,OEM,IdXML,AvitoId,НазваниеXML,ДатаСопоставления,ИсточникСопоставления,Комментарий
RS-00180081,Справочник.Номенклатура:...,1W2447,1W2447,reman8900001,7770000001,"Адаптер Caterpillar 1W2447",2026-06-03,manual,"Проверено вручную"
```

## Где хранить

Возможные варианты:

- регистр сведений 1С;
- дополнительный реквизит `Avito_ID` в номенклатуре;
- внешний Excel или CSV-файл на первом этапе;
- внутренняя таблица настроек внешней обработки.

## Правила

- Один `IdXML` не должен быть связан с несколькими товарами 1С.
- Один `КодНоменклатуры` не должен быть связан с несколькими активными объявлениями без явного комментария.
- Ручные сопоставления должны иметь источник `manual`.
- Спорные сопоставления нельзя применять молча.
