# Перенос Python-логики в BSL

Документ описывает, как проверенная логика Python-прототипа переносится в каркас внешней обработки 1С ERP 2.5.

Цель переноса — собрать первую внешнюю обработку, которая использует текущий XML Авито как шаблон, сопоставляет объявления с остатками 1С, формирует новый XML, ZIP с фото и CSV-отчёты.

Готовой `.epf` обработки в репозитории пока нет.

## Соответствие функций

| Python | BSL |
| --- | --- |
| `normalize_part` | `НормализоватьАртикул` |
| `split_part_numbers` | `РазбитьАртикулыНаКлючи` |
| `read_stock_excel` | `ПолучитьОстаткиERP` |
| `filter_stock_items` | `ОтфильтроватьОстатки` |
| `read_avito_xml` | `ПрочитатьТекущийXML` |
| `compare` | `СопоставитьXMLИОстатки` |
| `apply_xml_changes` | `СформироватьИтоговыйXML` |
| `ad_has_images` | `ЕстьФотоВXML` |
| `add_image_names_to_ad` | `ДобавитьФотоNameВXML` |

## Основные правила переноса

1. Текущий XML Авито используется как шаблон.
2. Старые `Id` объявлений не меняются.
3. `Title`, `Description`, категории Авито и существующий блок `Images` не пересобираются.
4. Новые товары автоматически в XML не добавляются, а попадают в отчёт `report_new_items.csv`.
5. Объявления менеджера `Юрий` не снимаются автоматически, даже если их нет в остатках 1С.
6. Товары с видом номенклатуры, содержащим `спецодежда`, исключаются из сопоставления и пишутся в `report_filtered_out.csv`.
7. Если в XML уже есть хотя бы один `<Image>`, блок `<Images>` запрещено перезаписывать.

## Нормализация артикулов

Python-функции `normalize_part` и `split_part_numbers` перенесены в BSL как:

- `НормализоватьАртикул`;
- `РазбитьАртикулыНаКлючи`.

Нормализация должна:

- приводить значение к верхнему регистру;
- заменять похожие русские буквы на латинские;
- удалять текст в скобках;
- удалять все символы кроме латинских букв и цифр;
- для числовых кодов добавлять вариант без ведущих нулей;
- для суффикса `RN` добавлять вариант без `RN`.

Примеры:

```text
270-5323 -> 2705323
3918776RN -> 3918776RN, 3918776
0406405520 -> 0406405520, 406405520
1W5009 (0.25) -> 1W5009
```

## Получение остатков

В Python остатки читались из Excel. В BSL они должны читаться из регистров ERP 2.5.

Функция `ПолучитьОстаткиERP` должна вернуть таблицу:

```text
Номенклатура
Код1С
Артикул
КатНомер2
Наименование
ВидНоменклатуры
Производитель
Склад
Остаток
Ключи
```

Точные регистры нужно проверить в конфигураторе. Черновики запросов находятся в `src/Запросы_ERP_2_5.bsl`.

## Фильтр хозяйственных товаров

Python-фильтр по колонке `Вид номенклатуры` переносится в BSL-функцию `ОтфильтроватьОстатки`.

Правило первого этапа:

```text
Если ВидНоменклатуры содержит "спецодежда", товар не участвует в сопоставлении.
```

Исключённые строки записываются в `report_filtered_out.csv`.

## Сопоставление

Функция `СопоставитьXMLИОстатки` должна построить индексы по множеству ключей:

- ключи XML берутся из `OEM`;
- ключи 1С берутся из `Артикул` и `КатНомер2`;
- если ключ встречается в нескольких объявлениях XML, он попадает в `report_duplicates.csv`;
- если у объявления нет ключа, оно попадает в ручную проверку;
- если совпадений несколько, объявление попадает в ручную проверку;
- если совпадение найдено и остаток больше нуля, объявление остаётся в XML;
- если совпадения нет и менеджер входит в список исключений, объявление остаётся в XML и попадает в ручную проверку;
- если совпадения нет и менеджер не исключение, объявление снимается.

## Формирование XML

Функция `СформироватьИтоговыйXML` должна работать с исходным XML-деревом:

- удалить только объявления из `КСнятию`;
- сохранить порядок объявлений;
- не менять `Id`;
- не менять `Title`;
- не менять `Description`;
- не менять категории Авито;
- не менять существующий `Images`;
- обновлять `Price` только если включена настройка `ОбновлятьЦены`.

Новые товары из 1С в XML автоматически не добавляются.

## Фото XML + ZIP

Python-функции `ad_has_images` и `add_image_names_to_ad` перенесены в BSL как:

- `ЕстьФотоВXML`;
- `ДобавитьФотоNameВXML`.

Критическое правило:

```text
Если в текущем XML уже есть хотя бы один Image, блок Images не трогать.
```

Если фото в XML нет, будущая реализация BSL должна:

1. Найти присоединённые файлы номенклатуры.
2. Отобрать `.jpg`, `.jpeg`, `.png`.
3. Ограничить количество настройкой `МаксимумФото`.
4. Сохранить файлы с именами `Код1С_1.jpg`, `Код1С_2.jpg`.
5. Добавить в XML:

```xml
<Images>
  <Image name="RS-00180081_1.jpg"/>
  <Image name="RS-00180081_2.jpg"/>
</Images>
```

6. Добавить сами файлы в `avito_photos.zip` без вложенных папок.

## Отчёты

Первый BSL-каркас формирует CSV-отчёты:

```text
report_summary.csv
report_exported.csv
report_removed.csv
report_new_items.csv
report_manual_check.csv
report_duplicates.csv
report_filtered_out.csv
report_photos.csv
report_errors.csv
```

CSV должны сохраняться в UTF-8 BOM или Windows-1251, чтобы открываться в Excel без проблем с русским текстом.

## Что нужно проверить в 1С

Перед сборкой `.epf` 1С-разработчику нужно уточнить:

1. Фактический регистр доступных остатков в ERP 2.5.25.101.
2. Фактический регистр цен типа цен `Кинезис`.
3. Где хранится `Кат. номер2`.
4. Где хранится дополнительный реквизит `Avito_ID`, если он будет использоваться.
5. Как получить двоичные данные присоединённых файлов номенклатуры.
6. Как корректно записывать ZIP в тонком клиенте и серверном режиме ERP.
