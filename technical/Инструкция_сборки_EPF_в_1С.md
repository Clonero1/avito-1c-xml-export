# Инструкция сборки EPF в 1С

Документ предназначен для 1С-разработчика, который будет переносить BSL-каркас из репозитория во внешнюю обработку `.epf`.

Codex не собирает `.epf` без 1С Конфигуратора. Репозиторий содержит BSL-каркас, технические документы и Python-прототип для сверки логики.

## 1. Создание внешней обработки

1. Открыть 1С Конфигуратор на копии базы ERP 2.5.25.101.
2. Создать новую внешнюю обработку.
3. Указать имя обработки, например `ВыгрузкаXMLАвито`.
4. Создать основную форму обработки.
5. Добавить реквизиты формы из раздела ниже.
6. Добавить команды формы:
   - `СформироватьВыгрузку`;
   - `ПроверитьДанные`;
   - `ОткрытьПапкуРезультата`.
7. Перенести код:
   - `src/МодульОбъекта.bsl` в модуль объекта обработки;
   - `src/МодульФормы.bsl` в модуль основной формы;
   - `src/Запросы_ERP_2_5.bsl` либо в общий модуль, либо в модуль объекта как отдельный блок функций.
8. Проверить синтаксис в Конфигураторе.
9. Заменить TODO-участки фактическими объектами ERP.

## 2. Реквизиты формы

| Реквизит | Предполагаемый тип 1С | Назначение |
| --- | --- | --- |
| `ПутьКТекущемуXML` | `Строка` | Полный путь к текущему XML Авито. |
| `ПапкаРезультата` | `Строка` | Каталог для итогового XML, ZIP и CSV-отчётов. |
| `ТипЦен` | `Строка` или `СправочникСсылка.ВидыЦен` | Тип цен `Кинезис`. Лучше использовать ссылку на вид цены. |
| `Склады` | `Массив` или табличная часть со ссылками на склады | Список складов для отбора остатков. |
| `ИсключатьВидыНоменклатуры` | `Массив` или список значений | Значения для исключения, по умолчанию `спецодежда`. |
| `НеСниматьМенеджеров` | `Массив` или список значений | Менеджеры-исключения, по умолчанию `Юрий`. |
| `ОбновлятьЦены` | `Булево` | Обновлять `<Price>` из ERP. На первом тесте выключить. |
| `ВыгружатьФото` | `Булево` | Формировать ZIP-фото и добавлять `Image name`, если в XML нет фото. |
| `МаксимумФото` | `Число` | Максимум фото на товар, по умолчанию `10`. |
| `СохранятьСуществующиеФотоXML` | `Булево` | Обязательное правило: существующий `Images` не перезаписывать. |

## 3. Команды формы

`СформироватьВыгрузку`:

- собирает параметры формы;
- вызывает `СформироватьВыгрузкуАвито(Параметры)`;
- формирует итоговый XML, ZIP-фото и отчёты.

`ПроверитьДанные`:

- читает XML;
- получает остатки и цены;
- применяет фильтр `спецодежда`;
- выполняет сопоставление без записи итогового XML и ZIP;
- показывает контрольные цифры.

`ОткрытьПапкуРезультата`:

- открывает или показывает путь к папке результата.

## 4. Что проверить в ERP

Перед рабочей сборкой обязательно проверить:

1. Фактический регистр остатков.
2. Фактический регистр цен.
3. Где хранится `Кат. номер2`.
4. Где хранится `Номенклатура.Вид номенклатуры`.
5. Где хранится производитель.
6. Как получить присоединённые файлы номенклатуры.
7. Как получить двоичные данные присоединённого файла.
8. Можно ли создавать ZIP из BSL в вашей среде.
9. Где безопасно сохранять временные фото.
10. В каком режиме будет запускаться обработка: толстый клиент, тонкий клиент, сервер.

## 5. Первый запуск

Порядок первого теста:

1. Запускать только на копии базы.
2. Выключить `ВыгружатьФото`.
3. Выключить `ОбновлятьЦены`.
4. Указать текущий рабочий XML Авито.
5. Указать отдельную папку результата.
6. Запустить `ПроверитьДанные`.
7. Сравнить количество:
   - объявлений в XML;
   - к снятию;
   - новых товаров;
   - ручной проверки;
   - дублей.
8. Сравнить результат с Python-прототипом.
9. Только после сверки запускать `СформироватьВыгрузку`.

## 6. Проверка результата

После формирования проверить:

- итоговый XML валидный;
- корень XML сохранился;
- старые `Id` не изменились;
- `Title`, `Description`, существующие `Images` не изменились;
- объявления `Юрий` не снялись;
- `спецодежда` попала в отчёт исключений;
- ZIP с фото не содержит вложенную папку;
- XML проходит проверку Авито.

## 7. Файлы результата

Ожидаемые файлы:

```text
avito_autoload_filtered.xml
avito_photos.zip
report_summary.csv
report_exported.csv
report_removed.csv
report_new_items.csv
report_manual_check.csv
report_duplicates.csv
report_filtered_out.csv
report_photos.csv
report_errors.csv
```

Если на первом запуске фото выключены, `avito_photos.zip` может не формироваться или быть пустым. Это допустимо для первого теста.

## Что в BSL-каркасе ещё требует реализации

BSL-файлы сейчас являются каркасом. Перед получением рабочей `.epf` 1С-разработчик должен реализовать TODO-участки:

- чтение текущего XML через XML API 1С;
- получение фактических остатков из регистров ERP;
- получение цен по типу цен `Кинезис`;
- получение дополнительных реквизитов, включая `Кат. номер2`;
- получение присоединённых файлов номенклатуры;
- получение двоичных данных фото;
- формирование итогового XML;
- запись CSV-отчётов;
- формирование ZIP-архива фото.

Нельзя считать `.epf` готовой только после копирования BSL-кода. Сначала нужно проверить синтаксис, заменить TODO и выполнить тест на копии базы.
